## Product
Providers (brands) register, get a subdomain storefront (`{slug}.platform.com`), create plans and sell subscriptions through Stripe Connect. Platform admins run everything. There is a payment retry (dunning) engine and a commission model. Roles: customer, provider_owner, admin, super_admin. Customers have ONE global account (single main database); a `provider_customers` link is created only when they actually subscribe or start a trial, never by visiting. Providers never see the global user table, only their own subscribers. On a storefront a signed-in customer sees a one-click "Continue as <name>"; a new visitor signs up.

## Gotchas learned (save yourself the time)
- Pest helpers for billing in `tests/Pest.php`: `liveStorefront()` (provider `acme` + active plan + synced price), `customerSession()`, `onStorefront('post', path, data)` (calls with the tenant host), `subscribe($user, $provider, $plan, $price, $overrides)` (local subscription plus its twin in the fake Stripe), `adminSession()`, `asGuest()` (the JWT library remembers the last token: `withoutToken()` alone still authenticates). `FakeStripeGateway` keeps subscriptions in memory; to simulate a Stripe failure bind an anonymous subclass. Money in tests is integer minor units.
- Stripe subscriptions: the checkout creates the `provider_customers` link, the Stripe customer and the incomplete subscription in one DB transaction; the customer becomes live only through webhooks (`SubscriptionSync`).
- Pest: JSON tests only send cookies after `->withCredentials()`; `withToken()` persists across requests in one test (use `->withoutToken()` for public calls); the JWT guard remembers the last user, so call `app('auth')->forgetGuards()` between requests as different users; roles live on guard `api` and the middleware syntax is `role:admin|super_admin,api`; helpers in `tests/Pest.php`: `loginAs`, `providerOwnerSession`, `fakeStripe`, `stripeWebhook`, `stripeEvent`; after `migrate:fresh` run `--seed` or roles are missing; `validated()` does not preserve the order of nested arrays (sort by key); `make:enum` lands in `app/`, move it to `app/Enums`.
- A JWT carries roles from login time: after something changes roles (e.g. provider registration) the SPA calls `refreshSession()`.
- Vitest: MSW is v3 (`onUnhandledFrame`, not `onUnhandledRequest`); jsdom URL is `http://localhost`; `testTimeout` is 15s and `asyncUtilTimeout` 4s (the first test of a file pays for imports); use `renderWithProviders` (`resources/js/test/render.tsx`); unmount (`cleanup()`) before clearing the auth store in `afterEach`; mock `@/lib/navigate` with `vi.hoisted`. Never `pkill -f vitest` in the same command as vitest (it kills your own shell); use a bracketed pattern like `pkill -f "[v]itest"`.
- shadcn CLI: it generates `import { cn } from "cn"` (an unrelated npm package); fix to `@/lib/utils`. `shadcn add --overwrite` resets `button.tsx` (our `loading` prop and `lg` size must be re-applied). Do not add `next-themes`.
- Scripted edits to prettier-formatted files can silently not match; re-read the file after editing. A missing route once caused an infinite `/admin` to `/login` redirect that hung Vitest.
- Playwright: `npm run build`, then `npm run e2e:serve` (serves with `APP_ENV=e2e`, which loads the full-copy, git-ignored `.env.e2e` with `AUTH_RATE_LIMIT=1000`; `artisan serve` ignores other env overrides and uses the dev SQLite DB). Seed an admin first: `php artisan app:create-admin e2e-admin@example.com --name="E2E Admin" --password='Password123!'`. Locators are strict and substring-matching: `getByLabel('Email')` also matches "Support email", `name: 'Publish'` also matches "Unpublish", `'Headline'` also matches "Subheadline"; use `exact: true` or scope to a row, dialog or list item. Wait for the next page's heading before filling a form after a navigation. Specs run serially. Clean the dev DB afterwards with `php artisan migrate:fresh --seed --force`.
- Event types and config keys contain dots; never use dotted config paths for them.
- Real `artisan serve` is single-threaded; running Vitest at the same time as other heavy processes causes timeouts, so run checks one after another.
